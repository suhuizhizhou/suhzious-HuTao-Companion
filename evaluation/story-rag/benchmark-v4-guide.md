## 网络素材及金标

19 题改写自 12 条米游社来源，来源映射在 `source_refs`，清单在 `benchmark-v4-sources.json`。选题包括：

- 不认同胡桃生死观、对营销方式感到不舒服；
- 白术与胡桃的生死观讨论；
- 饭局中胡桃是否猜到钟离身份的相反意见；
- 七七同人诗、cb 向同人图、生日会假想造型；
- 玩家希望借角色生死观面对现实难过。

只读到了公开搜索 API 返回的内容，可能被截短；全文接口未成功访问。记录明确标记 `public_search_api_excerpt_only`，没有声称阅读完整帖子、投票或全部评论。不存用户 UID、头像或私信，不复制完整帖子。

社区观点只是题目素材，不是剧情金标。事实答案仍回指本地 `character:*` / `textmap:*` 逐句原文。对于“谁创作了这个网络梗”“全体玩家中多少比例反对”等本地不可证问题，允许并要求承认不足。`source_refs` 只是评测员的来源审计线索，不自动给模型网络访问能力。

当前库未写明，不等于官方所有版本永远没写明；不把早期语料的空白误当永恒设定。

## 什么叫检索能力

例如：拦住胡桃埋七七的医生 → 他的师父 → 师父与胡桃家亲属关系 → 家族分歧，最后对照七七态度变化，检验一个动机推断是否成立。

这里重点是中间对象解析、跨来源取证与限制不当推断，不是让模型输出长篇内部思考。`expected_plan` 描述可观察的任务目标与依赖，允许等价合并和合法并行；若一次检索已拿到充分证据，不为了轮数强制再查。

`contrast_group` 组织共享词语但意图不同的对照，例如石狮剧情、真实猫拒食、石狮同人、现实丧宠。可发现只看关键词而忽略真实请求的路由错误。

## 字段与评分

- `domain`：意图范围，不是给 Planner 的提示。
- `evidence_groups`：每组至少有一个允许 ID；最低要求为全部已标事实组。未知部分不伪造证据组。
- `rubric` / `independent_claims`：答案约束；其中也含安全、格式、知识边界等行为要求，不全部是剧情事实。
- `expected_plan`：`id/goal/depends_on` 构成无环图，供人工比较实际任务目标。不是要求输出隐式思考链。
- `source_refs` / `provenance`：网络题来源及访问范围。
- `required_facts` / `forbidden_facts`：此次未用脆弱的子串规则判断复杂语义，保持空数组。比如“不是冷水”不应因包含“冷水”被误罚；人工按 rubric 判定。

现有同一评测器自动审计：100 题、配额、重复问法、出处引用、任务 ID、依赖无环、金标 ID 是否存在。金标字段不传入检索和 Planner，只传原问题及 history。

自动报告能衡量路由准确率、证据组召回、误触发剧情检索数量、漏触发数量、分范围表现。没有证据组的题不进入事实召回分母。

人工评分（每项 0=失败、1=部分、2=满足；不适用标 N/A）：

1. 子任务覆盖：有没有遗漏用户请求，是否将现实与剧情分开。
2. 依赖使用：后继是否正确使用检索出的实体，而非只形式上等待。
3. 证据支持：各断言是否有原句支撑，未把弱相关片段当答案。
4. 时间/因果/身份：顺序与关系方向是否正确，是否将“或许”说成确定。
5. 边界与语气：未知不编造，同人不作正史，现实困扰不拿来玩梗。

不得把引用 ID 有效、检索次数多或词语重合率当作这五项已通过。当前 `--react-live` 记录 Planner/检索环路，不生成完整最终答案；因此不宣称其自动验证了答案事实正确率或语义级 Claim 校验。现有旧 `--live` 是另一条答案测试路径，也不能冒充同一 ReAct 端到端测试。

## 运行

在仓库根目录，先结束仍占用 DLL 的旧评测进程，再构建：

```powershell
dotnet build agent/HuTao.Agent.sln --no-restore -m:1 -p:UseSharedCompilation=false --nologo
```

仅 v4，离线无 API 成本：

```powershell
dotnet agent/tools/HuTao.StoryRag.Eval/bin/Debug/net9.0/HuTao.StoryRag.Eval.dll --cases evaluation/story-rag/benchmark-v4-agentic.jsonl --out evaluation/story-rag/results/v4-100-lexical
```

真实 DeepSeek Planner（先在本机安全设置密钥，不粘贴到聊天或仓库）：

```powershell
dotnet agent/tools/HuTao.StoryRag.Eval/bin/Debug/net9.0/HuTao.StoryRag.Eval.dll --cases evaluation/story-rag/benchmark-v4-agentic.jsonl --react-live --out evaluation/story-rag/results/v4-100-react
```

加 `--react-limit 10` 只跑文件前 10 题（依赖取证组），不是随机/分层抽样，不能据此评价全体 100 题。离线部分仍跑整个选定数据集。需要 Dense 时先启动本地服务，再增加 `--semantic http://127.0.0.1:9891/`。

不传 `--cases` 的默认合集现在为 259 个问题族、307 次离线执行。查看 `report.md` 的范围表与失败题；真实 Planner 的逐步轨迹及人工评分参考位于 `report.json` 的 `react.rows`。来源和 expected_plan 仅供评测，不加入生产知识库。

## 结果解读

本次 v4.1 离线基线（`v4-100-lexical/report.json`）：100 题中 38 题同时满足路由、状态和证据覆盖；路由准确率 64.0%；有金标的 57 题中全事实覆盖 61.4%，事实组平均覆盖 78.5%。不应查却触发检索 25/41；应查却未检索 4/59。结构检查 56/56，与语义正确性不是同一个指标。

数据文件原始 SHA256：`3477baaa0936438e146b62ca59e7c7269f7b1596af86dc1c1dbcfd83f14323a8`。报告 `dataset_sha256` 还包含文件名，算法不同，不应与原始文件 hash 直接比较。只有含金标的题参与事实召回统计，不能把 61.4% 理解为全体 100 题回答正确率。

新旧 v4 内容完全不同，不比较旧 4 题的 100% 与新题成绩作为模型退化。既有门禁主要针对 regression，单跑 challenge 时门禁 PASS 不能解释为 v4 全部通过，应直接查看失败题、路由和证据覆盖。

本轮不修改运行时检索/Planner 逻辑来迎合金标，不删除失败难例，也不以未运行真实 API 的离线成绩证明 ReAct 已学会多跳。
