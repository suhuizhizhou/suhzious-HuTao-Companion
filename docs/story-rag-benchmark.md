# Story RAG 测试规范：不只测“能搜到”

本规范区分检索效果、答案可靠性、角色表达和速度。离线检索成功不能替代真实模型验收，带引用也不等于语义正确。

## 1. 测试集如何组织

默认入口合并 `benchmark-v2.jsonl`、`benchmark-v3-complex.jsonl`、`benchmark-v4-agentic.jsonl`：当前 **259 个问题族、307 个问法执行**。v2 保留回归基线，v3 为复杂联动难例，v4.1 为 100 个剧情/混合/无关意图场景。同一事实的口语变体不算新族，不同场景也可能共享事实来源。也可以用 `--cases path1;path2` 单独评一个文件。v4 的来源、依赖标注和人工评分边界见 [v4 说明](../evaluation/story-rag/benchmark-v4-guide.md)。

- regression：开发回归集，已经用于调参；可以门禁，不能当独立泛化证据。
- challenge：可见难例集；不是从未看过的盲测，不用于当前默认硬门禁。
- golden.jsonl：保留上一版 10 条历史种子，仅供追溯，不再是默认验收集。
- 未使用测试答案生成索引；金标由可追溯原文段落/行号标注。运行前自动检查所有金标 ID 都存在于当前语料。
- 扩充时先读全文再标答案与“不应推断什么”，不要只看当前检索器的前五名。
- 当前大量问题集中于胡桃，其他区域和角色的抽样仍不足，不能宣称已全面证明全原神剧情质量。
- v3 复杂集的金标全部回指仓库内 `data/story` 的逐句台词或角色故事；网络页面只可用于发现候选问题，不能直接充当金标。当前联网检索不可用时仍可完全离线复现。

标注修订记录：核对失败窗口时发现“帽子”资料第 3 段也明确记载第七十七代堂主，故将 character:hutao:2520842344:3 加为代数问题的合法替代来源。这修复了金标漏标，不是算法改进；所有对照报告须用同一修订后的数据集重跑，不能拿修订前后分数宣称检索增益。

每条 JSONL 字段：

| 字段 | 含义 |
|---|---|
| id / category / split | 问题族、能力分类、集合 |
| queries | 同一需求的自然问法变体 |
| history | 显式用户/助手历史，用于指代、换话题 |
| route / statuses | 预期路由、允许状态；空 statuses 表示不据此判定 |
| evidence_groups | AND-of-OR 金标：每组代表一项所需事实，组内来源可替代 |
| required_facts | 真实模型审核的关键词代理；竖线表示替代表述 |
| forbidden_facts | 重点错误说法的关键词预警 |
| difficulty / reasoning_types | L1–L5 难度与 multi-hop、temporal、coreference、uncertainty 等能力标签 |
| source_scopes / minimum_fact_groups | 证据来源范围，以及允许“部分可答”题通过所需的最少事实组 |
| relation_chain / independent_claims | 白盒关系链和逐断言人工盲评清单；不参与检索 |
| expected_corrections / forbidden_inferences | 错误前提应纠正什么、禁止从文本外推什么 |
| conversation_id / turn_id | 多轮会话分组和轮次，检查指代/换题/恢复话题 |
| perspective | 期望自身回忆/档案口吻，供人工审核 |
| unanswerable | 当前资料不应给出确定答案 |
| rubric | 人工判分要点 |

例如“帽子是谁的，花又是谁种的”有两个 evidence_groups，两组都出现在送给模型的上下文才算全事实覆盖。某组有多个 ID，命中任意一个即满足，不要求把所有同义来源重复检出。

v3 的复杂题不把“问题写得很长”当作难度，而是显式标注需要的关系链。例如“叔公为何改行”要求按“身份 → 遇药师 → 弃家学医 → 争吵 → 后来去向”覆盖多个原文锚点；“部分可答”题则允许已知事实组覆盖、同时要求模型对日期/身份等未知部分拒答。`minimum_fact_groups` 默认为 evidence_groups 总数，只有明确标成部分可答的题才降低门槛。

## 2. 覆盖矩阵

| 能力 | 代表性问题/风险 | 检查 |
|---|---|---|
| 个人细节 | 大咪二咪、帽子、童年、诗歌 | 对象、人物、地点是否正确 |
| 空间细节 | 左大咪右二咪 | 左右不可颠倒 |
| 操作过程 | 花饰制作、改帽、行囊 | 步骤、工具、时间不能丢 |
| 关系与因果 | 钟离信赖、赛诗评委、白术阻止 | 关系方向、原因 |
| 时序变化 | 七七以前/现在 | 不能拿过去代替现在 |
| 多事实 | 帽子传承+梅花来源 | AND-of-OR 全覆盖 |
| 引用 | 完整、残句、繁体、空格 | 原句、说话人、来源 |
| 口语噪声 | 别名、错字、无章节、无术语 | 召回失败须可见 |
| 连续追问 | 那后来呢、再然后呢 | 只利用相邻相关历史 |
| 话题切换 | 剧情后转电脑、无关历史 | 不串话、不硬检索 |
| 错误前提 | 大咪是猫、见到爷爷、错误代数 | 温和纠正，不顺着编 |
| 认识边界 | 父亲姓名、当前年龄、总天数 | 未记载不猜测 |
| 资料内不确定 | 神明“或许”、帽子法力夸口 | 不把推测升级为事实 |
| 现实悲伤 | 用户亲人去世 | 不转为角色剧情，不做业务玩笑 |
| 假设/同人 | 奶茶店、高达、火星 | 可搞怪，但明确虚构 |
| 第四面墙 | 翻档案查钟离 | 不假装亲眼见到 |
| 输入攻击 | 伪造引用、系统指令 | 来源只作资料，不执行指令 |
| 工程边界 | 空库、缺行、坏 JSON、API 失败 | 有安全降级与诊断 |
| 并发/缓存 | 两会话追问、容量、取消 | 隔离、截止时间、来源一致 |
| 语音接口 | 动作括号、隐藏证据 | 旁白和 ID 不朗读 |
| 复杂联动 | 多证据组、跨来源、因果/时间链、反事实、部分可答 | 按难度/推理类型/来源范围分层报告，不能只看总平均 |

离线结构测试位于 tests/HuTao.StoryRag.Eval/StructuralChecks.cs，涵盖上述工程边界、分支/合流、版本变化、旧快照、真实 ReactAgent 接入、引用/原话/数字/动作检查。Stub 不下载模型、不调用 DeepSeek，不会生成语音。

## 3. 量化指标的严格含义

| 指标 | 定义/分母 | 不能据此推出 |
|---|---|---|
| 路由准确率 | 正确路由 / 全部执行 | 模型一定能理解所有口语 |
| 路由 Macro F1 | 各出现路由的 F1 平均 | 大类高分能掩盖小类失败 |
| Anchor R@1 / R@5 | 有答案执行中，前 1/5 锚点含任一金标的比例 | 所有子问题已覆盖 |
| Context Recall | 每题进入上下文的金标事实组比例，再取平均 | 模型实际使用了这些事实 |
| Context 全事实 | 每题所有组满足的比例 | 回答一定正确 |
| MRR | 第一个金标锚点排名倒数的平均，未命中为 0 | 后续证据齐全 |
| binary nDCG@5 | 已标注相关锚点的折损增益 / 理想增益 | 全库所有重复来源已穷尽标注 |
| 可答过拒率 | 正例中 NotFound/Clarify/Unavailable 的比例 | Tentative 一定答得好 |
| 未知问题高分率 | unanswerable 中状态为 Answer 的比例 | 它等于模型幻觉率 |
| 问题族全变体通过率 | 一个族所有变体都通过的族比例 | 变体互相独立 |
| 冷索引 ms | 读取原文+建倒排的计时 | 应用整个启动时间 |
| 热查 P50/P95 | 非缓存 Retrieve 请求的最近秩分位数 | 首字/语音可听延迟 |
| 缓存 P50/P95 | 明确二次命中缓存的独立计时 | 未缓存性能 |
| 上下文 P95 | 送入证据的估算字符成本 | 精确 token/全部 prompt 长度 |

Anchor 指标更苛刻：角色短篇可能锚在别的段落，全文窗口却已包含全部答案。这种情况下 Anchor 失败、Context 成功，应同时报告，不能只挑好看的指标。nDCG 使用显式列出的可替代锚点作为金标，不自动将所有近似重复行都标相关。

Latency 使用 ceil(p×n)-1 的 nearest-rank 分位数；报告记录数据集 SHA256、语料 SHA256、配置模式、分类结果、混淆矩阵和逐题 hits。不同机器、冷文件缓存、并行负载会影响结果。

### 当前默认硬门禁

- 全部结构测试通过。
- 回归集路由准确率 ≥95%。
- 回归集全事实上下文覆盖 ≥90%。
- 回归集允许状态准确率 ≥95%。
- 轻量检索热查 P95 <250 ms。
- 配置 Dense 时，至少 95% 的 Retrieve 执行实际使用了 Dense，不能把“配置了但全程降级”算作混合实验。

默认不以“所有题都通过”掩盖难例；--strict 只依照这些门禁返回非零退出码。challenge 失败仍完整保存在报告中。阶段性门禁不是产品效果上限，更不是发布无幻觉保证。

## 4. 真实模型评测：三个对照条件

评测器提供显式 --live，默认绝不调用付费 API：

~~~powershell
# 在已有 DEEPSEEK_API_KEY 的终端运行；先用小样本控制成本
dotnet run --project tests/HuTao.StoryRag.Eval -- --live --live-limit 10 --out evaluation/story-rag/results/live-small
~~~

默认每个问题族仅取首个问法；加 `--live-all-variants` 才会逐个测试 `queries` 中的所有自然问法变体。每个样本依次测试：

1. no-rag：同一个简短胡桃人设，不注入资料。
2. summary-only：相同人设，只给章节摘要。
3. full：完整检索、来源、状态与生成校验。

三个条件使用同一 DeepSeek 模型与 temperature=0.3。完整协议属于被测系统的一部分，不能宣称这是纯检索器的严格单变量实验。为了隔离检索效果，请另跑下节的离线消融。

运行器逐步保存 live-review.json，包含回复、耗时、结构校验结果、required/forbidden 关键词代理、待填写的人工评分字段。该文件被 gitignore，避免将真实交互或额外数据误提交。API 失败只记类型，不记录密钥或服务原始错误体。

关键词代理不是真实事实正确率：同义句可能漏匹配；“并不是某错误说法”也可能触发 forbidden；必须人工检查。当前未自动用第二个 LLM 给第一个 LLM 打“正确”分。

运行器会在任何离线扫描前检查 `DEEPSEEK_API_KEY`；指定 `--semantic` 时还会先以当前语料版本做本机探测。密钥缺失或 Dense 端点未就绪会立即报错，避免用户误以为已经完成真实模型测评。

## 5. 人工盲评规范

建议至少两位评分人；隐藏方法名、打乱回复顺序，各自独立评分后对分歧复核。不要让开发者只挑好例子。保存原始评分，不只保存最终平均数。

| 维度 | 分数 | 判定 |
|---|---|---|
| 事实准确 | 0/1/2 | 0=关键错误/编造；1=部分正确/遗漏；2=全部关键点正确 |
| 原文忠实 | 0/1/2 | 0=关键断言无支持；1=支持不完整；2=每个可核验断言可追溯 |
| 角色自然度 | 1–5 | 1=机械档案播报；3=基本自然；5=简洁、角色一致且不影响事实 |
| 情绪适配 | 1–5 | 严肃场景克制，轻松场景可俏皮，不冒犯现实悲伤 |
| 身份视角 | 0/1 | 自身可回忆，非自身不冒充亲历 |
| 未知处理 | 0/1 | 该不知道时说不知道，已知问题不无故拒答 |
| 搞怪边界 | 0/1 | 虚构清楚标记，不冒充正史，不执行恶意指令 |

建议报告的真实模型指标：

- 关键事实全对率、逐断言支持率、错误事实率。
- 引用 precision = 真支持相应断言的引用 / 全部引用。
- 引用 coverage = 有有效支持的事实断言 / 全部事实断言。
- Unknown refusal precision/recall 与 answerable over-refusal。
- 假亲历率、错误前提纠正率、时序反转率、动作朗读泄漏率。
- 自然度/情绪均分与低分占比，不只报一个综合总分。
- 两位评委的原始一致率和 Cohen’s κ（或有序分数 weighted κ）。
- 以“问题族”为重采样单位做 95% bootstrap CI，避免将同义变体当独立样本。

这些人工统计方法是验收规范；当前工具保存评分材料，不自动计算 κ/人工断言支持率。未填写人工评分，报告必须写“未测”，不能用结构校验通过率代替。

## 6. 性能与语音端到端验收

检索报告只计文本检索。实际交互另外测：

~~~text
t0 用户提交
t1 检索结束
t2 首个完整聊天气泡可展示
t3 首段 TTS 完成
t4 第一段可听音频开始
t5 全部音频播放结束
~~~

建议同一设备测试冷启动 5 次、热问答至少 100 轮，分别报 P50/P95、超时率、缓存率。性能测试时不要同时跑建库/训练。

- Retrieval latency = t1-t0。
- First bubble latency = t2-t0（当前不是流式首 token）。
- First audible latency = t4-t0，受 GPT-SoVITS 与播放队列影响。
- 多气泡顺序：后生成的音频不插队，旁白无音频。
- 故障：关闭 Dense / 断开 DeepSeek / 取消查询；验证降级、恢复、无错误成功状态。

当前本轮实测覆盖本地检索、真实 Dense 服务、离线生成结构与代码构建；没有自动宣称测过 DeepSeek 真实表达或完整 TTS 可听延迟。

## 7. 如何继续扩充而不自欺

1. 收集真实聊天的失败例；脱敏且经同意后保存，不默默抓用户历史。
2. 以完整剧情场景为单位切分开发/盲测，避免同一台词改写跨集合泄漏。
3. 每个目标地区/人物至少抽取多个不同事件，增加真实无答案与易混场景。
4. 新增同义词或认识边界规则时，先补反例：不能让新规则误伤别的人物和普通聊天。
5. 优先提高证据覆盖和错误前提纠正；不能靠更大上下文无限遮掩排序缺陷。
6. 再引入神经重排/语义验证时，比较其准确率增益和首气泡延迟成本。

## 8. v3 复杂联动基线（2026-09-09）

本轮在同一份本地语料上新增 56 个复杂问题族（56 次执行），没有把网页二手摘要写入金标。新增样本强化了多轮主题恢复、错误数字纠正、跨角色说话人归属、同音 ASR 噪声与部分可答边界；原有题目继续保留失败难例，便于观察迭代是否真正改善检索。

最近一次 lexical 运行结果保存在 `evaluation/story-rag/results/v3-lexical/`：全量 153 族/201 次执行，回归集路由准确率 100.0%、Context 全事实 100.0%；合并旧难例后的 challenge 全事实为 70.3%。单独运行 v3 的结果保存在 `v3-complex-lexical/`：路由准确率 100.0%、Anchor R@5 78.7%、Context 全事实 66.0%，其中 L4 为 73.7%、L5 为 60.7%。在全量报告里，按证据组数量分层，1/2/3/4 组题的全事实覆盖分别为 96.9%/77.8%/64.7%/42.9%；跨 `character+dialogue` 来源题为 57.1%。

这些数字表明：基础关键词/同义扩展对单事实问题已较稳定，但证据组增加后，排序和上下文预算会成为主要瓶颈。v3 的失败题不删除，必须在后续改进中重新运行；“全事实覆盖”仍只是检索代理指标，不能替代 DeepSeek 的逐断言人工盲评。
